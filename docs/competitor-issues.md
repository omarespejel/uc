# Issues hit in scarb, snforge and sncast while testing uc

Observed on 2026-10-25 while running `uc` side by side with scarb 2.18.0, snforge 0.60.0 / 0.54.0 and sncast 0.60.0 on real projects: OpenZeppelin v3 git dependencies (erc8004, agent-account, session-account), registry dependencies (token-factory, betshare) and garaga (shhh-wallet). Every row is reproducible from a plain checkout.

| # | Tool | What happened | Why it hurts | Seen on |
|---|------|---------------|--------------|---------|
| 1 | scarb 2.18.0 | A registry index cache written by an older scarb is unreadable: `failed to deserialize index record from cache ... missing field 'kind' ... cache is corrupted and is in unrecoverable state`. Every build with a registry dependency fails until the user runs `scarb cache clean`. | Hard stop after a scarb upgrade; no automatic migration, no hint in the build output until you read the full error. | token-factory (`openzeppelin_token = "0.20.0"`), betshare (`openzeppelin = "2.0.0"`) |
| 2 | snforge 0.60.0 | Project pins `snforge_std = "0.54.1"`. snforge runs anyway and 17+ tests fail with `Reading from buffer failed ... Probably snforge_std/sncast_std version is incompatible` buried inside panic data. Only a soft warning at the top. | Developers see a wall of red that has nothing to do with their contract. uc's built-in cheatcode runtime is version independent and ran the same 168 tests green. | erc8004 |
| 3 | snforge 0.54.0 + scarb 2.18.0 | `Error during libfunc specialization ... Could not specialize libfunc get_execution_info_v3_syscall`. An older snforge cannot run Sierra produced by a newer scarb and reports a compiler-internal error instead of a version message. | Pinning the matching snforge for an old `snforge_std` does not help once scarb moved on; the toolchain matrix locks in. | betshare, erc8004 |
| 4 | snforge 0.60.0 | Cold `snforge test` on 41 tests: 45 s (betshare); 168 tests: 25 s (erc8004). Every run recompiles the test crate through scarb. | Slow inner loop. uc (warm) runs the 41 betshare tests in 0.6 s and the 168 erc8004 tests in 28 s; on heavy contract-call tests snforge is still about 3x faster per test. | betshare, erc8004 |
| 5 | scarb 2.18.0 | Cold `scarb build` on erc8004 (6 contracts, OZ v3): 15 s; warm rebuild of the same tree: 7 s. uc builds the byte-identical artifacts in 2.9 s. | | erc8004 |
| 6 | Blast API public RPC (default in scarb/foundry docs and many SDKs) | `https://starknet-mainnet.public.blastapi.io/rpc/v0_7` now answers every call with `Blast API is no longer available. Please update your integration to use Alchemy`. Lava's public endpoint says `This endpoint has been discontinued`; Nethermind's free RPC returns empty bodies. | Any tool shipping these as defaults (uc did too until today) breaks silently for read commands and trace/audit. uc now defaults to Cartridge's keyless public RPC and reports the endpoint it used in every JSON report. | all on-chain commands |
| 7 | scarb 2.18.0 | When `Scarb.lock` needs refreshing (a dev-dependency pin changed), `scarb build` and `snforge test` contact the registry even though every package is already in the local cache, and a dropped connection fails the build with `client error (Connect)`. | Offline or flaky-network builds fail for a lookup that is not needed. uc resolves from the cache first and only fetches what is missing. | erc8004, agent-account copies during the head-to-head run |

Things uc had to get right because the tools above do not: a single binary that carries its own corelib and compiler (no `asdf`, no `scarb` cache migrations), byte-identical artifacts to scarb 2.18 (verified on all 13 erc8004 artifacts: Sierra, CASM and `starknet_artifacts.json`), a cheatcode runtime that does not care which `snforge_std` the manifest pins, and a native registry client that downloads, checksums and extracts `scarbs.xyz` packages into the cache layout scarb uses (uc reuses scarb's downloads; scarb's own ledger does not see uc's).

## uc's own bugs found by the same method (2026-10-26)

| Area | What happened | Fixed by |
| :--- | :--- | :--- |
| Class hash | uc hashed the ABI pretty-printed; the network hashes the string as declared, which starknet-rs sends in Python's JSON form. Every uc class hash differed from the chain's. | pythonic ABI serialization; golden test against a node-attested hash |
| DECLARE | the transaction never carried the class and sent `class_hash`, a field nodes reject | class embedded, derived field stripped |
| Nonces | lookups used block id `pending`, which RPC 0.10 renamed `pre_confirmed`; the error was swallowed and every write sent nonce 0 | `latest`, errors surfaced |
| Signatures | write commands signed a Poseidon hash of three fields instead of the SNIP-8 transaction hash | SNIP-8 V3 hashing; vectors attested by starknet-devnet 0.10.1 |
| Fee bounds | a failed estimate was ignored and the default L2 gas bound was zero, so every transaction was rejected for insufficient resources | estimate failure stops the send; non-zero defaults |
