Working on Cairo & Starknet Projects

scarb 2.18.0 snforge 0.60.0 sncast 0.60.0 starknet-devnet-rs uc prove (Symbolic + Caracal)

uc is a self-contained Cairo and Starknet project manager, compiler, test runner, formal verification engine and chain CLI written in Rust. It replaces scarb, snforge and sncast in a single static binary with the Cairo 2.18.0 compiler and corelib embedded, and launches starknet-devnet when one is installed. uc --version prints the compiler and Sierra versions in use.

Tip: Zero-Configuration Compatibility
uc reads your existing Scarb.toml, Scarb.lock, and snfoundry.toml files directly. You do not need to migrate manifests or rewrite tests.

Installation (Linux & macOS)

uc ships as a single self-contained binary for Linux (x86_64-unknown-linux-gnu, aarch64-unknown-linux-gnu) and macOS (Apple Silicon aarch64-apple-darwin, Intel x86_64-apple-darwin). The Cairo standard library (corelib) is embedded directly inside the binary and extracted on first run to ~/.uc/cache/.

macOS & Linux (Standalone Installer)sh
# Install uc into ~/.local/bin
curl -LsSf https://raw.githubusercontent.com/omarespejel/uc/main/install.sh | sh

# Install uc AND create drop-in symlinks for scarb, snforge, sncast, and starknet-devnet
curl -LsSf https://raw.githubusercontent.com/omarespejel/uc/main/install.sh | sh -s -- --drop-in
GitHub Actions (.github/workflows/ci.yml)yaml
steps:
  - uses: actions/checkout@v4
  - uses: omarespejel/uc@v1
    with:
      drop-in-symlinks: true
  - run: uc prove && uc test

Drop-In Tool Replacement (`argv[0]` Multi-Call Binary)

Like BusyBox or uv, uc inspects argv[0] at startup. When invoked via a symlink named scarb, snforge, sncast, or starknet-devnet, it adapts its CLI routing to match that tool:

Earlier the same day, on the same tree and a quieter machine: cold scarb build on erc8004 15.0 s, warm 7.0 s, warm uc build 2.9 s producing the 13 byte-identical files; snforge test 24.6 s for the 168 tests (cold, includes compile) versus uc test 28 s warm. The erc8004 suite is dominated by six tests that each execute 1.2 to 1.9 million VM steps across hundreds of nested contract calls; snforge runs those about 3x faster per test because uc reloads the whole CASM program for every nested call. That is the one place where uc is slower, and it is on the roadmap.

Where uc wins and why: warm uc build and uc check answer from a fingerprint that covers sources, dependencies, lockfile and compiler version, so an unchanged tree costs about 20 to 30 ms; cold builds skip scarb's process spawn and metadata round trips; unit and cheatcode tests run in-process with a lazy VM memory path, so betshare's 41 tests take 0.85 s warm against 2.43 s for snforge.

Project Structure

A Cairo project is defined by a Scarb.toml manifest at its root, alongside a deterministic Scarb.lock lockfile and optional snfoundry.toml network profiles:

Workspace Layouttree
my_vault/
├── Scarb.toml          # Package metadata, edition, dependencies, and [[target.starknet-contract]]
├── Scarb.lock          # Exact resolved dependency versions and checksums
├── snfoundry.toml      # Optional [sncast.] RPC URLs, account names, and keystores
├── src/
│   └── lib.cairo       # Root Cairo module and #[starknet::contract] definitions
└── tests/
    └── test_vault.cairo # Integration tests using snforge_std cheatcodes
Scarb.tomltoml
[package]
name = "my_vault"
version = "0.1.0"
edition = "2024_07"

[dependencies]
starknet = ">=2.14.0"

[[target.starknet-contract]]
sierra = true
casm = true

Creating & Initializing Projects

Use uc new <path> to scaffold a new package or uc init inside an existing directory:

Terminalbash
$ uc new my_vault
Created package `my_vault` at my_vault/Scarb.toml

$ cd my_vault
$ uc check
uc check: my_vault (1 modules, 0 contracts) -> ok in 277.4ms   # cold; a cache hit answers in about 1 ms

Managing Dependencies

Modify dependencies declaratively with uc add and uc rm, inspect the dependency graph with uc tree, or update lockfiles with uc update:

Terminalbash
$ uc add openzeppelin_token@3.0.0
$ uc add --dev snforge_std@0.60.0
$ uc tree
my_vault v0.1.0
├── openzeppelin_token v3.0.0
└── starknet v2.18.0
$ uc fetch                       # resolve and download registry packages natively
uc fetch: 5 fetched, 0 cached (2241.3ms)

Registry packages are resolved from Scarb.lock when present (exact versions, checksums from the lock) or from the scarbs.xyz index (highest version matching the requirement, caret semantics), downloaded over HTTPS, SHA-256 verified and extracted into scarb's cache layout. uc reuses whatever scarb already downloaded; scarb keeps a separate download ledger and does not pick up uc's downloads. uc check and uc build do this automatically; set UC_REGISTRY_FETCH=0 to disable network access.

Compiling, Checking & Executing

uc embeds the Cairo compiler (`cairo-lang-*`) and maintains a persistent Salsa incremental database plus a content-addressed BLAKE3 CASM cache in .uc/.

CommandDescription
uc checkRun syntax, macro expansion, semantic, and lowering diagnostics without Sierra/CASM codegen.
uc buildCompile Sierra (.contract_class.json, .sierra.json) and CASM (.compiled_contract_class.json) into target/dev/.
uc execute --arguments 15,27Compile and run a standalone #[executable] or main function in-process (alias: uc cairo-run).
uc doc --openExtract Cairo docstrings and build HTML/Markdown API documentation (alias: uc mdbook).
uc optimize-inliningSweep inlining-strategy weights (`--min-threshold 0 --max-threshold 250 --step 25`) to minimize CASM size or L2 gas.
uc package / uc publishPack a distributable .tar.zst archive or publish to a Scarb registry.

Testing, Fuzzing & `snforge_std` Cheatcodes

uc test executes both standard #[test] functions and Starknet Foundry (snforge_std) contract tests in-process. You do not need to download an external snforge_std git repository—uc injects a native snforge_std shim automatically.

Terminalbash
# Run all unit & integration tests with coverage-guided fuzzing
$ uc test --fuzzer-runs 256 --fuzzer-seed 42 --gas-report

# Run tests against live forked Starknet Mainnet/Sepolia state
$ uc test --fork-url https://api.cartridge.gg/x/starknet/sepolia

# CI sharding, fail-fast, and re-running only failed tests
$ uc test --partition 1/4 --exit-first
$ uc test --rerun-failed
Supported In-Process `snforge_std` Cheatcodes
declare, ContractClassTrait::precalculate_address, deploy, deploy_at, start_cheat_caller_address, stop_cheat_caller_address, start_cheat_block_timestamp, start_cheat_block_number, start_cheat_sequencer_address, start_cheat_tx_info, spy_events, EventSpyAssertionsTrait, start_mock_call, stop_mock_call, replace_bytecode, get_class_hash, load, store, map_entry_address, and generate_random_felt.

Formal Verification & Symbolic Execution (`uc prove`)

Unit tests only check individual inputs. uc prove lowers your Cairo code to Sierra SSA IR and runs three verification passes (sub-second on typical packages; 161 functions of erc8004 in about one second):

  1. Symbolic Path & Interval Solver: Explores every control-flow branch in Sierra SSA IR (up to 1024 statements per path and 1024 paths per function), tracks algebraic constraints including Cairo 2.18's bounded-int lowering of checked arithmetic, and classifies each function: PROVEN_SAFE (every panic path explored, none satisfiable), GUARDED_SAFE (panics only behind caller or calldata guards), COUNTEREXAMPLE_FOUND (concrete inputs, emitted as parameter values and as wrapper calldata, replayed through the entry point on a fresh state), BOUNDED_SAFE (budget hit) or UNDECIDED (solver gave up). Counterexamples are reported only where the caller chooses the values; a bound-hitting overflow inside a helper is a precondition on its caller. --emit-smt <dir> writes every panic path as an SMT-LIB obligation with the expected verdict; benchmarks/scripts/check_smt_obligations.py checks them with z3 or cvc5 (z3 agreed on all 7,698 decided erc8004 obligations and all 1,566 STRK obligations on 2026-10-25). uc audit <address> --live-storage decides state-dependent paths against the contract's real storage.
  2. Sierra taint detectors (Caracal-style, but on Sierra so they also run on deployed classes with no debug names): unprotected state mutation and arbitrary calls on the entry surface, check-effects-interactions (a lock slot that is read, written before the call and written back after it is recognised: the release is not reported and writes under the lock are Low; a pre-call write that was never read is called out as not a lock), caller-controlled loop bounds (interprocedural, numeric parameters only, capped bounds and calldata-array lengths excluded), unvalidated storage writes in constructors and setters, swallowed syscall errors, redundant DivRem and bitwise parity. Builtin pointers (RangeCheck, Pedersen) never carry taint. #[test] bodies are not symbolic targets; prove_*, invariant_* and check_* functions are.
  3. Medusa Stateful Invariant Campaign: Executes randomized multi-transaction sequences (`#[invariant]` / `invariant_*`) against `StarknetState` and shrinks any violating call sequence.
Terminal Outputbash
$ uc prove --sarif report.sarif
Package `my_vault` (14 Sierra functions, 412 statements):
  ✓ compute_settlement   GUARDED_SAFE  (preconditions: ["amount <= 10000", "rate_bps <= 250"])
  ✗ unsafe_mul_fee       COUNTEREXAMPLE_FOUND (witness: amount = 18446744073709551615, fee_bps = 2)

$ uc audit 0x04718f5a0fc34cc1af16a1cdee98ffb20c31f5cd61d6ab07201858f4287c938d --network mainnet --json
# the deployed STRK token, no source: 178 functions, 106 proven safe, 72 guarded, 0 counterexamples, 5 findings

uc audit takes a contract address, a class hash, a .contract_class.json or a Scarb.toml. For deployed classes the entry points are named from the ABI by selector and PanicResult is recognised structurally, so every detector above runs on bytecode. benchmarks/scripts/run_mainnet_audit.py audits 20 well-known mainnet contracts this way (16 Sierra classes, 2,843 functions, 92 findings, 23 counterexamples; 32 s on an idle machine, 118 s at load average 60) and writes the results to benchmarks/results/.

Watching a Deployment, Upgrade Gate, Starkscan

uc watch <address> polls the class hash at an address, re-audits when it changes and lists the findings and counterexamples that appeared or disappeared relative to the previous class (--once --json for cron; state in .uc/watch/). uc declare -c Vault --upgrade-of <address> fetches the deployed class and refuses to build the transaction when a storage slot or entry point disappears, calldata arity changes or a caller guard is lost (--allow-unsafe-upgrade overrides); uc prove --check-upgrade 0x... runs the same comparison. With STARKSCAN_API_KEY set, --network presets use Starkscan's JSON-RPC gateway, uc trace labels every address through Starkscan and names every call from the ABI of the class that ran it, uc audit reports the Starkscan verification record, and uc audit --declared-since <block> emits an audit entry for every class declared in a block range. uc test --gas-report adds builtin instance counts and a resource-gas breakdown per test (Starknet's L2 gas weights per step and builtin) with the heaviest tests ranked.

Formal Equivalence & Upgrade Safety

When refactoring a contract for gas optimization or preparing a proxy upgrade (`replace_class_syscall`), `uc prove` can mathematically verify compatibility against a baseline version:

Terminalbash
# Prove mathematical equivalence (return values + panic conditions + storage writes) across all inputs
$ uc prove --manifest-path v2/Scarb.toml --check-equivalence v1/Scarb.toml

# Verify storage slot layout & selector compatibility before an upgrade
$ uc prove --manifest-path v2/Scarb.toml --check-upgrade v1/Scarb.toml

# Audit a raw compiled .sierra.json or .contract_class.json without source code
$ uc prove --sierra-file target/dev/my_vault.contract_class.json

Sierra Decompiler & Transaction Autopsy

Because Starknet contracts preserve typed Sierra SSA IR, uc decompile reconstructs readable pseudo-Cairo from any compiled artifact, and uc trace decodes nested transaction execution traces:

Terminalbash
# Reconstruct readable Cairo from a compiled ContractClass or Sierra JSON
$ uc decompile target/dev/my_vault.contract_class.json -o decompiled.cairo

# Decode a Starknet transaction call tree, storage diffs, L2 gas, and revert reason
$ uc trace 0x049d36570d4e46f48e99674bd3fcc84644ddd6b96f7c741b1562b82f9e004dc7 --rpc-url $RPC_URL

Auto-Remediation (`uc lint --fix`) & Stwo Circle STARK Profiler

Under StarkWare's Stwo (Circle STARK) prover (Haböck, Levit, Papini 2024), proving time is governed by AIR builtin table multiplicities (`Pedersen`, `Poseidon`, `RangeCheck`, `Bitwise`, `Blake2s`). uc profile --prover-air computes exact builtin multiplicities per function, and uc lint --fix automatically patches Cairo anti-patterns in place:

Terminalbash
# Preview or apply automatic security & gas rewrites (LegacyMap -> Map, DivRem fusion)
$ uc lint --diff
$ uc lint --fix

# Profile Stwo Circle STARK AIR builtin multiplicities & CASM size
$ uc profile --prover-air

Local Devnet (`uc devnet` / `starknet-devnet-rs`)

uc devnet (aliased as uc node and symlink-compatible with starknet-devnet) runs a Starknet chain inside the uc process. On start it compiles three embedded Cairo 2.18 contracts with its own compiler (an account, an ERC20 fee token, a universal deployer; cached per compiler version), deploys the tokens at the mainnet STRK and ETH addresses and the deployer at the mainnet UDC address, and funds the predeployed accounts. Each declared class gets a Sierra runner sharing one class table, so calls cross classes declared at any time. Served: declare, deploy_account and invoke transactions with nonce checks, starknet_call, nonces, classes, storage, receipts with events and nested revert reasons, blocks, getEvents, state updates, traces, and the devnet_* mint, createBlock, setTime and increaseTime routes. Fees are not charged and signatures are not checked. --backend starknet-devnet launches an external binary instead.

Terminalbash
# Start local Starknet devnet on port 5050 with 10 predeployed accounts & deterministic seed
$ uc devnet --port 5050 --seed 42 --accounts 10

# Start devnet forked from Starknet Mainnet or Sepolia at a specific block
$ uc devnet --port 5050 --fork-network https://api.cartridge.gg/x/starknet/mainnet --fork-block 900000

# Export predeployed accounts as JSON for scripts & CI
$ uc devnet --dump-accounts --json

Declaring, Deploying & Multicall (`sncast` Parity)

The sncast 0.60.0 subcommands run natively inside uc. RPC resolution: --url, else STARKNET_RPC, else the snfoundry.toml profile, else --network mainnet|sepolia|devnet (Cartridge public endpoints). Every JSON report includes rpc_url.

Terminalbash
$ uc declare --contract-name my_vault_contract --url http://127.0.0.1:5050/rpc
$ uc deploy --class-hash 0x01a2... --constructor-calldata 0x1 0x2
$ uc invoke --contract-address 0x049d... --function compute_settlement --arguments "1000, 50"
$ uc call --contract-address 0x04718f5a...938d --function name --network mainnet
$ uc balance --token strk --account 0x4678...61b5 --network mainnet
Balance: 41163.469472512870815086 STRK
$ uc get nonce 0x4678...61b5 --network mainnet
Nonce for 0x4678...61b5 at latest: 0xbc694b
$ uc trace 0x76029f41...de8 --network mainnet --json      # starknet_traceTransaction, decoded
$ uc multicall run calls.toml --url http://127.0.0.1:5050/rpc

AI Agents & MCP Server (`uc mcp`)

Every uc command accepts --json and --report-path <file> for deterministic machine parsing (`schema_version: 1`). uc mcp serve prints a read-only JSON catalog of commands and their report schemas that an MCP adapter can wrap as tools; it is not an MCP server by itself. uc lsp starts the language server (LSP 3.17 over stdio).
